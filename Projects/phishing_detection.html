01
THE QUESTION

Before following a suspicious link, what can the link itself tell us?

A phishing page does not need to look obviously malicious. The transition often happens in a single click.

Modern phishing imitates trusted brands with familiar wording and urgent calls to action. The URL is a small artifact, but its hostname, path and structure can still preserve measurable clues about the destination behind it.

This project treats the URL (and optional authorised HTML) as evidence. It extracts a fixed set of signals, compares them with labelled examples, and surfaces the observations so a person can decide what deserves further investigation.

THESIS

The goal is not an automated verdict. It is a structured inspection that supports cautious review before the click.

02
DATA

Turning URLs and optional HTML into a fixed 53-feature vector.

The model never fetches the live website. It only analyses material the user already has.
01

34 URL Features

Lengths, punctuation, IP hosts, HTTPS, subdomain depth, shortened domains, suspicious TLDs and credential-related keywords.

02

19 HTML Features

Forms, password fields, links, scripts, iframes, login patterns and selected JavaScript cues (zero-filled when HTML is absent).

05
LIMITATIONS

Where the current detector still has clear boundaries.

01

No Live Inspection

The system never fetches the destination. It only analyses the URL and any HTML the user already possesses.

02

Evolving Attacks

Phishing techniques change continuously. Static feature assumptions can become less representative over time.

03

False Positives & Negatives

Legitimate pages can look suspicious; sophisticated phishing can avoid obvious signals. Both error types have real consequences.

04

Small Experiment

The reported metrics come from a 1,000-record sample (800/200 split). They are not a deployment benchmark.

IMPORTANT

Treat every prediction as triage support, never as authorisation to click. A “benign” label is not a safety guarantee.

06
